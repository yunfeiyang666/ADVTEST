# RQ1、RQ2 现有结果与模型微调讨论稿

> 更新时间：2026-07-14  
> 用途：与老师讨论当前实验结论，以及是否开始模型微调实验。  
> 说明：本文区分“可作为当前结论的正式结果”和“仍需补齐方法边界的预实验结果”。

## 1. 现在已经做到了什么

目前两条研究线已经形成了一个可以闭环的故事：

- **RQ1：VQA 模型错误检测。** 用不同方法生成测试问题，比较它们能暴露多少 VQA 模型错误，并分析错误集中在哪些能力上。
- **RQ2：覆盖率。** 在同样的题目数量下，比较不同选题策略覆盖了多少场景图结构；同时验证 ADVTEST 能否在大规模帧上持续生成并逐步补齐覆盖缺口。
- **下一步微调。** 用 RQ2 的覆盖引导生成训练数据，再用冻结的 RQ1 测试集检查微调后模型是否减少了这些错误。

## 2. RQ1：VQA 模型错误率

### 2.1 三种方法的基础对比

下面采用带对象 ID 标注图像、每种方法 1000 道新题、同一个 mPLUG-Owl2 模型的结果。这里使用开放问答形式，便于保持三种方法原有输出形式。

| 方法 | 题数 | 错题数 | 错误率 | 不重复错题数 | 说明 |
|---|---:|---:|---:|---:|---|
| ADVTEST | 1000 | 902 | 90.2% | 902 | 当前混合题池几乎被 converge 支配，不代表均衡 L2 |
| QATest | 1000 | 152 | 15.2% | 117 | 基于正确 seed 做文本变形，检测能力较弱 |
| QAAskeR | 1000 | 58 | 5.8% | 17 | 可成功生成的 follow-up 种类少，强行补到 1000 后重复明显 |

这张表当前可以说明：在同样 1000 道新题的预算下，ADVTEST 生成的问题更容易暴露模型错误。但是不能直接把 90.2% 当作最终综合检错率，因为其中 949/955 的可转换 mixed 题属于 converge，题型比例严重失衡。

### 2.2 ADVTEST 分层结果

严格开放问答版每项均为 1000 题：

| 层级或题型 | 错误率 | 当前解释 |
|---|---:|---|
| L0 | 45.2% | 类型、状态、数量等单对象信息；部分错误来自同义词和自动判分过严 |
| L1 | 64.0% | 对象间方向、关系和带条件计数，比 L0 明显更难 |
| L2-converge | 90.3% | 多条空间约束共同锁定一个对象，模型常不能输出正确对象 ID |
| L2-direction_chain | 83.8% | 模型存在明显 yes 倾向，开放回答也带来额外判分损失 |
| L2-distance_chain | 52.9% | 相对距离比较错误，结果相对稳定 |
| L2-viewpoint_transfer | 48.3% | 原版只要求 left/right，考察视角转换 |

选择题版用于排除同义表达、输出格式和自由生成 ID 的影响：

| 层级或题型 | 选择题错误率 | 与开放问答版相比 |
|---|---:|---:|
| L0 | 36.2% | -9.0 个百分点 |
| L1 | 56.1% | -7.9 个百分点 |
| L2-converge | 58.7% | -31.6 个百分点 |
| L2-direction_chain | 12.0% | -71.8 个百分点 |
| L2-distance_chain | 51.3% | -1.6 个百分点 |
| L2-viewpoint_transfer（v7 六方向） | 81.9% | +33.6 个百分点 |

这里最重要的判断是：

- L0、L1 在选择题下仍有较高错误率，说明不能全部归因于自动判分。
- converge 选择题仍错 58.7%，说明即使给出同类对象选项，多约束定位仍然困难。
- direction_chain 降到 12.0%，说明其严格版高错误率很大一部分来自 yes/no 表达和判分形式，不能作为最强检错证据。
- distance_chain 两版几乎不变，是当前较干净的空间推理错误信号。
- viewpoint_transfer 的 v7 题目把二分类改成六方向分类，而且 `back (otherwise)` 对模型产生明显诱导，因此 81.9% 不能直接作为最终结果。

### 2.3 viewpoint_transfer 修正实验

| 版本 | 题数 | 错误率 | 结论 |
|---|---:|---:|---|
| 原开放问答 left/right | 1000 | 48.3% | 二方向任务，不能与六方向直接比难度 |
| v7 六方向，含 `back (otherwise)` | 1000 | 81.9% | 存在明显选项措辞诱导 |
| 六方向，明确写出 back 角度范围 | 1000 | 73.9% | 去掉诱导后下降 8.0 个百分点 |
| 四方向 front/left/back/right | 1000 | 66.0% | 粒度放宽后继续下降，但视角转换仍然较难 |

因此，viewpoint_transfer 的错误率上涨由两部分共同造成：六方向任务本身更难，以及 `otherwise` 带来的额外诱导。最终正式题库应统一写出每个方向的明确角度范围，不再使用 `otherwise`。

### 2.4 RQ1 目前能下的结论

1. ADVTEST 能生成大量让 VQA 模型答错的问题，检错能力明显强于当前 QATest、QAAskeR 对照。
2. ADVTEST 的优势不能只用一个混合错误率表示，必须按 L0、L1 和四类 L2 分别报告。
3. 当前最可信的难点是：converge 多约束定位、distance_chain 距离比较、L1 复合关系，以及修正提示后的 viewpoint_transfer。
4. direction_chain 的严格版错误率受输出形式影响较大，应降级为辅助结果。
5. 自动判分和题目提示仍需最后清理，尤其是同义词、状态题、方向角度和 `otherwise`。

## 3. RQ2：覆盖率

### 3.1 原始 NuScenes-QA 的初始覆盖

在 6011 帧统计中，原始数据对结构空间的平均初始覆盖为：

| 层级 | 初始覆盖率 |
|---|---:|
| L0 | 49.5% |
| L1 | 4.7% |
| L2 | 0.6% |

这说明原始问题能够覆盖约一半对象级信息，但对关系和三对象结构覆盖非常不足，尤其 L2 几乎为空。这是继续做主动生成的直接依据。

### 3.2 ADVTEST 全量生成能力

全量 6011 帧实验已经验证 ADVTEST 可以从初始覆盖出发持续补齐缺口：

| 场景规模 | L2 归一化预算 AUC | L2 绝对题量 AUC |
|---|---:|---:|
| 小场景 S（3-15 个对象） | 0.548 | 0.851 |
| 中场景 M（16-30 个对象） | 0.571 | 0.807 |
| 大场景 L（不少于 31 个对象） | 0.561 | 0.833 |

达到全覆盖时的全量统计为：

- 总 L2 缺口：45,225,720。
- 总生成题数：38,380,168。
- 平均每题覆盖 1.1784 个 L2 缺口。
- 题数约为 L2 缺口数的 84.86%。

这组结果主要证明方法可扩展、能够最终补齐覆盖；它不是同一 1000 题预算下的方法对比。

### 3.3 固定 1000 题预算的对照预实验

当前较合理的预实验使用 30 帧公共池、每种方法 1000 题、每帧最多 50 题，因此实际覆盖相同的 20 帧：

| 方法 | 覆盖 L2 数 | 总 L2 数 | L2 覆盖率 | 每题覆盖 L2 数 | L2 AUC |
|---|---:|---:|---:|---:|---:|
| ADVTEST | 2809 | 539733 | 0.520% | 2.809 | 0.0025 |
| Random | 2441 | 539733 | 0.452% | 2.441 | 0.0021 |
| QATest 预实验 | 2423 | 539733 | 0.449% | 2.423 | 0.0020 |
| QAAskeR 预实验 | 1265 | 539733 | 0.234% | 1.265 | 0.0011 |

在该设置下，ADVTEST 比 Random 多覆盖 368 个 L2，提升约 15.1%；比 QATest 预实验多覆盖 386 个，提升约 15.9%。

另一组每帧最多 100 题的敏感性实验只访问 11 帧，ADVTEST 每题覆盖 2.590 个 L2，Random 为 1.584，优势更大。但由于帧数更少、单帧题目更多，不适合作为主结果，只能说明帧内深挖时覆盖引导的作用更明显。

### 3.4 RQ2 结果的边界

固定预算表目前仍应标为预实验，原因如下：

- Random 可以作为内部消融，但必须是从完整可生成空间中真正随机选题，不能复用 ADVTEST 排好序后的结果。
- QATest、QAAskeR 应使用各自原始生成逻辑；如果无法输出我们的 L2 结构字段，就不能直接声称它们在结构覆盖上落后。
- 最终主表应固定同一批帧、同一 1000 题预算、相同图像输入，并分别报告覆盖 L0/L1/L2、每题新增覆盖数和覆盖曲线 AUC。

因此，当前可以稳妥地说：ADVTEST 相比 Random 的覆盖引导有效；与 QATest、QAAskeR 的结构覆盖对比仍需把各方法独立生成和覆盖映射口径彻底固定。

## 4. 是否可以开始模型微调

可以开始，但应先做一个规模受控的试点，而不是立即把全部生成题用于训练。微调实验可以成为 RQ1 和 RQ2 的连接实验：**覆盖更全面的生成数据，是否真的能修复 VQA 模型的薄弱能力。**

### 4.1 建议的第一轮实验组

所有组使用相同模型、相同训练题数、相同训练轮数：

| 训练组 | 训练数据 | 目的 |
|---|---|---|
| Base | 不微调 | 给出原模型错误率 |
| Official | NuScenes-QA 原始题 | 检查普通数据扩充能带来多少收益 |
| Random | 从可生成题中随机取相同题数 | 排除“只是训练题更多”的影响 |
| ADVTEST | 按覆盖缺口选择相同题数 | 检查覆盖引导是否带来更大提升 |
| ADVTEST-balanced | L0、L1、四类 L2 均衡采样 | 检查题型失衡是否影响微调效果 |

第一轮建议先用 20k-50k 题做 LoRA/QLoRA 试点。跑通后再扩大到 100k 或更多，不需要一开始就使用千万级全覆盖数据。

### 4.2 数据划分必须遵守的条件

1. 按 scene 划分训练、验证和测试，不能把同一 scene 的相邻帧分到两边。
2. 当前 RQ1 的正式测试帧全部冻结，不进入微调训练集。
3. 同一个对象关系或同一道题的改写不能跨训练集和测试集。
4. 训练图像继续使用对象 ID 标注版本，否则题目里的 `car14`、`barrier3` 对模型不可见。
5. 方向题全部改成明确角度范围，删除 `otherwise` 后再进入训练集。

### 4.3 微调后看什么

主指标不是训练损失，而是冻结测试集上的变化：

- RQ1：L0、L1、converge、direction_chain、distance_chain、viewpoint_transfer 各自错误率。
- RQ2：训练数据在 L0/L1/L2 上的覆盖率，以及相同训练题数下的覆盖差异。
- 官方题：NuScenes-QA 准确率，确认模型没有为了结构题而明显退化。
- 数据效率：每增加 1000 道训练题，RQ1 错误率下降多少。
- 泛化：在训练中未出现的新 scene 上是否仍有提升。

### 4.4 开始微调前必须完成的最小清理

- 修正方向规则中的 `otherwise`，重新生成所有受影响的正式训练题。
- 固定状态和类别同义词表，避免把 `walking/moving`、`person/pedestrian` 当成错误标签。
- 对每类模板抽样人工检查，确认问题、GT、对象 ID 和图像标注一致。
- 建立训练集清单，记录每题来源、scene、层级、题型、覆盖结构和生成版本。
- 冻结一份不再修改的 RQ1 测试集，微调期间只用于评估。

## 5. 建议和老师重点讨论的五个问题

1. RQ1 最终主结果采用开放问答、选择题，还是两种都报告？建议两种都保留：开放问答更接近真实使用，选择题用于排除表达和自动判分影响。
2. RQ1 的综合 L2 题型比例如何定？建议先分题型报告，不急着用一个失衡的 mixed 数字代表全部 L2。
3. RQ2 是否只把 Random 作为严格覆盖对照，而把 QATest、QAAskeR 作为检错率对照？这可能比强行把外部方法映射到我们的 L2 覆盖空间更严谨。
4. 微调的目标是提高 NuScenes-QA 整体准确率，还是重点修复复杂空间推理？两者决定训练数据中 L0/L1/L2 的比例。
5. 暑假阶段的终点是完成一个模型上的 LoRA 证明，还是增加第二个 VQA 模型验证泛化？建议先完成一个模型的完整闭环，再考虑第二个模型。

## 6. 当前建议

RQ1 已经基本具备“发现模型薄弱能力”的证据，RQ2 已经证明覆盖引导有效且能够大规模生成。现在可以启动微调试点，但正式训练前需要先完成方向提示、自动判分和训练/测试隔离这三项清理。

暑假内最现实的目标是：完成一套冻结数据划分，在同等训练预算下比较 Official、Random、ADVTEST 和 ADVTEST-balanced，证明覆盖引导生成的数据不仅覆盖更多结构，而且能更有效地降低未见场景上的 VQA 错误率。
