# V18 Gap优先级修复 - 优先覆盖L0/L1

## 问题总结

### 问题1：每题耗时0.5s，不是0.1s

**真相**：
- LLM生成时间：764ms / 4题 = 191ms/题 ✅ 很快
- 总流程时间：2035ms / 4题 = 508ms/题 ❌ 慢

**瓶颈**：Excel写入耗时7782ms（不是LLM）

### 问题2：缺口选择固定性太大

**现象**：
- 77轮才达到100%覆盖
- L2B占86%（180/210题）
- L0/L1覆盖很慢

**原因**：评分函数只考虑L0节点，不考虑L1边

## 解决方案

### 修改的文件

**文件**：`run_method_a.py`  
**位置**：第1416-1421行  
**修改内容**：改进 `_gap_score` 函数

### 核心改进

1. ✅ 考虑L1边的覆盖情况
2. ✅ 分阶段动态调整权重
3. ✅ 评分范围扩大到1-401（区分度大幅提升）
4. ✅ 优先选择包含未覆盖L0/L1的gap

### 评分对比

| 场景 | 旧评分 | 新评分 | 优先级变化 |
|------|--------|--------|-----------|
| 3个未覆盖L0 + 2个未覆盖L1 | 4 | 401 | ⬆️ 100倍 |
| 1个未覆盖L0 + 1个未覆盖L1 | 2 | 151 | ⬆️ 75倍 |
| 全部已覆盖（纯L2） | 1 | 1 | 持平 |

## 预期效果

- **当前**：77轮达到100%覆盖
- **改进后**：预计40-50轮达到100%覆盖
