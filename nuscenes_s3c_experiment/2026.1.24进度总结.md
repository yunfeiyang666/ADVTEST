## 阶段 3：解决“远距离物体筛选 + 图中打标”问题，降低答题难度

这步是为“人类/模型都更容易理解场景 & 出题”做准备。

可以分两块：

1. **远距离物体筛选标准**
   - 分析 NuScenes 官方 QA 对“视野内 / 可见 / 太远不管”的 implicit 规则：
     - 比如基于 ego 的距离阈值（10m / 20m / 25m？）；
     - 是否限定一定方向（前方 ±45°）内的对象才会进入题干。
   - 在场景图生成阶段增加一个过滤字段，例如：
     - `visible_for_qa = True/False`，基于我们确定下来的距离+角度规则；
   - 让后续出题和推理只考虑 `visible_for_qa=True` 的对象，减少“图上虽有但谁都不关心”的噪声。

2. **图像打标 & 对应关系**
   - 在 BEV / 原始相机图像上，为每个 `unique_id`（car2, pedestrian3, ...）画框+文字标注；
   - 确保:
     - 问题里提到的“the truck to the back right of the with rider thing”对应哪些框；
     - 最后答案中的对象（或者“是/否”对比的那两个对象）也能在图上被清楚地看到；
   - 后续在让大模型答题时，输入不仅有自然语言和“scene graph 文字摘要”，还包括：
     - 场景图中该对象的属性（type/status/位置关系）；
     - 图像上清晰的编号和位置，降低“光凭想象配图”的难度。

## 阶段 4：根据覆盖率指导，自动生成高覆盖率数据集（蜕生模型）

最终目标你已经说得很清楚：在“蜕生模型”框架下，让大模型自己根据覆盖率去产生新题+新答案。

这个阶段的大致流程可以是：

1. **以当前白名单模板为蓝本**（Pattern A/B + 多锚点等），从真实场景图中 **自动抽取结构化 QueryPlan/Cypher**：
   - 例如：
     - 选一个 `not standing pedestrian` + `back-right bus` + `front bus of trailer` 三元组；
     - 通过 Neo4j 直接计算标准答案（same_status true/false 或 count 数字）。
2. **用 L 等级覆盖率信息指导采样**：
   - 优先针对未覆盖或稀疏覆盖的 L‑单位（边/路径/模式）生成问题；
   - 确保新数据集对任务空间有更高的 coverage，而不是重复已有结构。
3. **让大模型“自然语言化”问题与答案**：
   - 给 LLM 输入：
     - 模板类型 + 填好的对象/方位/status；
     - 来自 Neo4j 的正式答案；
   - 要求它输出：
     - 一个自然语言问题；
     - 一段对应的自然语言答案描述（与 label 一致）。
4. **用现有 VQA Pipeline 自验证**：
   - 把这些自动生成的问题再丢回“自然语言→Cypher→Neo4j→答案”的流水线；
   - 如果 pipeline 能重现同样的 label，则这个问答对通过；
   - 如不能，再结合 prompt / 模板调整，形成闭环优化。

## 🧠 二、几何与场景图语义

### 2.1 Source‑centric 方向定义

文件：`vqa_pipeline/direction_utils.py`、`generate_selected_scenes.py`

- 相对角度计算现在为：

  ```python
  rel = target_translation - source_translation
  world_angle = atan2(rel_y, rel_x)
  yaw = quaternion_to_yaw(source_rotation)      # 源对象自身 yaw
  rel_deg = normalize(world_angle - yaw)       # [-180, 180]
```
- 关系方向字段：
  - `predicates[0]` / `direction_8`：精细 8 向（front / front-left / ...）。
  - `direction_4`：4 向聚合（front / back / left / right）。
  - `predicates[1]` / `distance` / `angle`：分别为距离级别、精确距离、角度。

- 所有 6 个覆盖场景（特别是 `scene-0553_frame8_scene_graph.json`）已用此定义重算并存储在：

### 2.2 8 向 & 4 向叠加关系

在 `SCENE_GRAPH_SCHEMA` + Prompt 中统一描述：

- **8 向（精细）** — 用于题面中出现 “front-left / back-right / ...” 等复合方位：
  - 查询条件：`WHERE r.predicates[0] = 'front-left'` 等。
- **4 向（宽锥）** — 用于题面仅说 “front / back / left / right”：
  - 查询条件：`WHERE r.direction_4 = 'front'`；

  - 只给一个方向词时自动落在“宽扇区”。

## 📐 三、VQA Prompt & few‑shot 设计

### 3.1 Prompt 主体结构（`vqa_pipeline/config.py` 中的 `QUESTION_TO_CYPHER_PROMPT`）

关键内容：

1. **Schema 说明**：节点 / 关系字段、状态字段、方位设置；
2. **对象/类型规范**：
   - trailer 用 `category CONTAINS 'trailer'`；
   - truck 应排除 trailer：`type='truck' AND NOT category CONTAINS 'trailer'`；
   - motorcycle 可以用 `type='motorcycle'` 或 `category CONTAINS 'motorcycle'`。
3. **方位规则（非常强调）**：
   - 单向 front/back/left/right → `r.direction_4`；
   - 复合方位 front-left/back-right → `r.predicates[0]`；
   - 句式 “X to the DIR of Y” 必须写成 `MATCH (Y)-[r]->(X)`。
4. **抽象模式 A/B**：
   - **Pattern A**：两个通过空间关系定义的对象的 status 比较；
   - **Pattern B**：先通过空间关系定义一个对象，再找“same status 的 other X”。

5. **输出格式约定**：

```text
   【THINK】...【/THINK】     # 可选思考
   【CYPHER】
   MATCH ...
   ...
   RETURN ...
   【/CYPHER】               # 必须且只允许一条查询、一个 RETURN
```
   - 明确禁止使用 ``` 代码块；解析端只看 `【CYPHER】...【/CYPHER】`。

6. **重试反馈位**：

```text
   上一次错误信息(如果是重试且有错误提示，请参考并避免同样问题): {prev_error}
```
   - `prev_error` 由 pipeline 在前一次生成失败时填入，用于指导下一轮修正。

### 3.2 15 道 few‑shot 示例（Pattern A/B + 多锚点）

位置：`QUESTION_TO_CYPHER_PROMPT` 中 **抽象模式 A/B** 段后，`输出格式约定` 前。

- 格式：

```text
  【示例k - 描述】
  自然语言问题:
  "..."

  【THINK】
  1. ...
  2. ...
  【/THINK】
  【CYPHER_EXAMPLE】
  MATCH ...
  ...
  RETURN ...
  【/CYPHER_EXAMPLE】
```
- 覆盖代表题型（只列几个关键）：

  - **Q8（最关键）**：  
    “Is the status of the bus to the back right of the not standing pedestrian the same as the bus that is to the front of the stopped trailer?”
    - 以 not‑standing pedestrian 为参照选 `back-right` bus1；  
    - 以 stopped trailer 为参照选 `front` bus2（`direction_4='front'`）；  
    - 比较 `bus1.status = bus2.status`。

  - **bus vs truck（with_rider thing back-right）**：
    - ped back-right bus1 vs with_rider back-right truck1。

  - **barrier front of trailer 计数**：
    - 以 trailer 为参照，`direction_4='front'` 统计 barrier 数量。

  - **barrier front-left of bicycle → same-status other bicycles**（Pattern B）：
    - bicycle front-left barrier → barrier.status → other bicycles with same status。

  - **多锚点交集：trailer back-right & truck back**：
    - 在 stopped trailer 的 back-right 且在 stopped truck 的 back 上的 target（barrier）。

  - **motorcycle vs pedestrian / car**（back-right of with_rider / not‑standing ped）；

  - **other things same status as truck**（Pattern B，动态类型集合）；

  - **ego 前方 standing pedestrian**；

  - 以及几道我们目前做错但结构特别好的题，例如：
    - front-left stopped things of trailer；
    - motorcycle back-right & ego front-left；
    - moving thing back-right of ego & bus 等。

> few‑shot 只用 `【CYPHER_EXAMPLE】`，不会被 parser 误读为真实输出。

## 🔄 四、生成 & 抽取 & 重试机制

### 4.1 Cypher 生成（`LLMClient.generate_cypher`）

- 构造 prompt：`QUESTION_TO_CYPHER_PROMPT.format(schema=..., question=..., question_type=..., prev_error=...)`  
  - 注意：为了避免 `.format` 把 Cypher 里的 `{}` 当占位符，few‑shot 中所有 `{...}` 都写成 `{{...}}`。
- 调用 `chat()` 与模型交互；
- 解析步骤：
  1. 剪掉 `<think>...</think>`；
  2. 去掉 ``` 代码块；
  3. **优先匹配**：`【CYPHER】(.*?)【/CYPHER】`；
  4. 若无 block，则回退到老的 heuristics（按行过滤 MATCH/RETURN 等）。

- 如解析不到合法查询，抛异常，由上层 retry。

### 4.2 高层重试（`VQAPipeline.process_question`）

- 若 `use_ir=False`（当前主线），则：

```python
  max_gen_tries = config.MAX_RETRIES (默认 3)
  last_error_msg = None

  for attempt in range(max_gen_tries):
      feedback = last_error_msg if attempt > 0 else None
      cypher_query = llm.generate_cypher(..., feedback=feedback)
      # 成功则 break
      # 失败则记录 last_error_msg = str(e)
  else:
      raise RuntimeError(f"多次尝试(共{max_gen_tries}次)仍未生成有效的Cypher查询: {last_error_msg}")
```
- 这样可以在第一轮“输出为空 / 少 RETURN / 有语法问题”时，把错误信息喂回模型，后两轮更有针对性。

+    """问题分析器"""
+    
+    # 对象类型关键词
+    OBJECT_TYPES = {
+        'car', 'truck', 'bus', 'pedestrian', 'bicycle', 
+        'motorcycle', 'trailer', 'barrier', 'vehicle', 'object'
+    }
+    
+    # 方向关键词
+    DIRECTIONS = {
+        'front', 'back', 'left', 'right', 
+        'front-left', 'front-right', 'back-left', 'back-right',
+        'ahead', 'behind', 'forward', 'rear'
+    }
+    
+    # 属性关键词
+    ATTRIBUTES = {
+        'status', 'moving', 'stopped', 'parked', 'standing',
+        'with_rider', 'without_rider', 'rider'
+    }
+    
+    # 问题类型模式
+    COUNT_PATTERNS = [

+    ]
+

+    ]

+    
+    IDENTIFICATION_PATTERNS = [
+        r'what is', r'which', r'what\s+\w+\s+is', r'closest', r'nearest', r'farthest'
+    ]

+    def analyze(self, question: str, answer: str) -> QuestionFeatures:

+        features = QuestionFeatures(question=question, answer=answer)
+        
+        q_lower = question.lower()
+        
+        # 1. 分析问题类型
+        features.question_type = self._classify_question_type(q_lower)
+        
+        # 2. 提取对象类型
+        features.mentioned_objects = self._extract_object_types(q_lower)
+        
+        # 3. 提取特定对象ID
+        features.specific_ids = self._extract_specific_ids(q_lower)

+    def _classify_question_type(self, q_lower: str) -> str:
+        """分类问题类型"""
+        for pattern in self.COUNT_PATTERNS:
+            if re.search(pattern, q_lower):
+                return 'count'
+

+        
+        for pattern in self.ATTRIBUTE_PATTERNS:

+        found = set()
+        for obj_type in self.OBJECT_TYPES:
+            if obj_type in q_lower:

+        return found
+    
+    def _extract_specific_ids(self, q_lower: str) -> Set[str]:
+        """提取特定对象ID"""
+        # 匹配 car1, pedestrian2 等
+        pattern = r'\b(car|truck|pedestrian|bicycle|motorcycle|bus|trailer|barrier)(\d+)\b'
+        matches = re.findall(pattern, q_lower)
+        return {f"{obj_type}{num}" for obj_type, num in matches}
+    
+    def _involves_ego(self, q_lower: str) -> bool:

+        ego_patterns = ['ego', ' me ', ' my ', ' i ', 'myself']
+        return any(p in q_lower or q_lower.startswith(p.strip()) or q_lower.endswith(p.strip())

+        found = []
+

+        compound_directions = ['front-left', 'front-right', 'back-left', 'back-right',

+        for direction in compound_directions:

+

+        
+        return found

+        # 两跳的标志
+        two_hop_indicators = [

+        ]

## 覆盖率评估系统 - 技术总结

### 一、三维场景图模型（赛博城市）

```
        Z轴 (属性层)
        │  ┌─ category
        │  ├─ status     ← "坐电梯"
        │  └─ type
        │     │
    ════╪═════●══════[RELATES_TO]══════●════  ← "走道路"
        │   car1                   pedestrian1
        │
        X-Y平面 (拓扑层)
```
---

### 二、覆盖率指标定义

| 层级   | 名称     | 定义                        | 赛博城市比喻 |
| ------ | -------- | --------------------------- | ------------ |
| **L0** | 节点覆盖 | 查询实际命中的对象节点      | 点亮地基     |
| **L1** | 边覆盖   | 关系边(水平) + 属性边(垂直) | 单步移动     |
| **L2** | 两跳覆盖 | 连续两条边的路径            | 连续两步     |

**L1边的两种类型**：
- **关系边**：`(car1)-[RELATES_TO]->(pedestrian1)`                                           — 水平道路
- **属性边**：`(car1)-[has]->(status:moving)`                                                      — 垂直电梯

**L2路径的两种类型**：
- **Rel→Prop**：`car1 → pedestrian1 → status:standing `                                — 走到邻居家+坐电梯
- **Rel→Rel**：`ego → car1 → pedestrian1`                                                              — 连续串门（稀有）

---

### 三、统计模式："中选"模式

| 特性             | 说明                                   |
| ---------------- | -------------------------------------- |
| **保留LIMIT**    | 只统计查询实际返回的对象               |
| **去重机制**     | 使用`Set`类型，多题覆盖同一节点只算1次 |
| **有效节点过滤** | 只统计场景图中存在的节点，防止数据污染 |
| **动态执行优先** | 只有查询执行失败才启用静态分析fallback |

---

### 四、关键代码逻辑

```python
# 1. 注入RETURN语句，保留LIMIT
pattern = r'RETURN\s+.*?(?=\s+LIMIT|\s+ORDER\s+BY|$)'
new_cypher = re.sub(pattern, f'RETURN {node_ids}, {edge_ids}', cypher)

# 2. 动态执行 → 只有执行失败才fallback
if result['success'] and result['data']:
    # 提取实际命中的节点/边
elif not result['success']:
    # 语法错误等 → 静态分析fallback
# else: 执行成功但返回0行 → 确实没有匹配，覆盖=0

# 3. 有效节点过滤
if self.valid_nodes:
    nodes = nodes & self.valid_nodes
```

让我用一个具体例子完整走一遍流程：

### 问题: "What is the status of the car to the front of the bus?"

---

#### Step 1: LLM生成Cypher

```cypher
MATCH (bus:Object)-[r:RELATES_TO]->(car:Object)
WHERE bus.type = 'bus' 
  AND car.type = 'car'
  AND 'front' IN r.angle_matches_ego
RETURN car.status AS result
LIMIT 1
```
---

#### Step 2: 注入变量，保留LIMIT

```cypher
MATCH (bus:Object)-[r:RELATES_TO]->(car:Object)
WHERE bus.type = 'bus' 
  AND car.type = 'car'
  AND 'front' IN r.angle_matches_ego
RETURN bus.unique_id AS bus_id, 
       car.unique_id AS car_id,
       startNode(r).unique_id AS r_src, 
       endNode(r).unique_id AS r_tgt
LIMIT 1   ← 保留！只返回1行
```
---

#### Step 3: 在Neo4j执行，获取实际结果

```
返回1行数据:
{
  bus_id: "bus1",
  car_id: "car3",
  r_src: "bus1",
  r_tgt: "car3"
}
```
---

#### Step 4: 提取覆盖元素

**从返回数据提取：**

```python
# L0 节点：从 *_id 字段提取
nodes = {"bus1", "car3"}

# L1 关系边：从 r_src, r_tgt 提取
rel_edges = {("bus1", "car3")}
```
**从Cypher语法提取属性访问：**

```python
# 扫描Cypher中访问了哪些属性
# bus.type, car.type, car.status
props_accessed = {"type", "status"}

# L1 属性边：对已覆盖节点的属性
prop_edges = {
    ("bus1", "type:bus"),
    ("car3", "type:car"),
    ("car3", "status:stopped")  # 假设car3的status是stopped
}
```
---

#### Step 5: 计算L2两跳路径

```python
# Rel→Prop：关系边的终点 + 该终点的属性
for (src, tgt) in rel_edges:           # ("bus1", "car3")
    for (node, prop) in prop_edges:
        if node == tgt:                 # car3 == car3 ✓
            L2.add((src, tgt, prop))

# 结果:
L2 = {
    ("bus1", "car3", "type:car"),
    ("bus1", "car3", "status:stopped")
}
```

### 最终覆盖统计

| 层级   | 覆盖内容                                                     | 数量    |
| ------ | ------------------------------------------------------------ | ------- |
| **L0** | `{bus1, car3}`                                               | 2个节点 |
| **L1** | 关系: `{(bus1→car3)}`<br>属性: `{(bus1,type:bus), (car3,type:car), (car3,status:stopped)}` | 4条边   |
| **L2** | `{(bus1→car3→type:car), (bus1→car3→status:stopped)}`         | 2条路径 |

### 关键约束

| 约束                   | 实现方式                           |
| ---------------------- | ---------------------------------- |
| **只统计实际命中**     | 保留`LIMIT 1`，只看返回的那1行数据 |
| **节点必须在场景图中** | `nodes & valid_nodes` 过滤         |
| **L2必须逻辑连通**     | 关系边终点 == 属性边起点           |
| **去重**               | 使用`Set`类型                      |
