# RQ1 Experiment Boundaries Design

## Goal

Build a defensible RQ1 evaluation in which methods share only neutral inputs and
evaluation infrastructure, while each method retains its own question-generation
or question-selection behavior.

## Experimental Layers

### Layer 1: Structural Coverage Baselines

This layer isolates the value of ADVTEST's coverage guidance. All methods receive
the same frame order and the same complete programmatically generatable question
space for each frame.

Methods:

- `advtest`: use the existing coverage-prioritized order and adaptive frame switch.
- `random`: uniformly shuffle the complete question space. It must not inspect
  gaps, current coverage, marginal gain, or ADVTEST ordering when deciding where
  to sample or when to switch frames.
- `template_balanced`: round-robin across template families without coverage
  feedback.
- `object_balanced`: greedily balance question counts across involved objects,
  without using L1/L2 coverage.
- `greedy_l0`: maximize newly covered objects only.
- `greedy_l1`: maximize newly covered one-hop relations only.

The first four are generic sampling baselines. `greedy_l0` and `greedy_l1` are
component-level baselines that show whether multi-level coverage is necessary.

Comparable metrics:

- L0/L1/L2 micro and macro coverage.
- Unique L2 items per generated question.
- Area under the coverage-budget curve.
- Failure discovery metrics after VLM evaluation.

### Layer 2: Cross-Paradigm Error Detection

This layer compares end-to-end testing paradigms. Methods share official
NuScenes-QA records as neutral seeds and may not consume ADVTEST-generated
questions or ADVTEST-private metadata.

Methods:

- `official_qa`: evaluate the original official questions.
- `qatest`: mutate official NuScenes-QA questions using QATest transformations.
- `qaasker`: generate follow-up questions from official QA and the SUT's initial
  answers, following QAAskeR's metamorphic relations.
- `advtest`: independently generate structure-aware questions from the scene
  graph.
- `random_generation`: independently sample from the complete programmatically
  generatable question space without coverage feedback.

Comparable metrics:

- Unique verified failures per VLM call.
- VLM calls per new failure.
- Failure category diversity.
- Duplicate failure rate.
- Frame, object category, and relation distribution of failures.

Structural coverage is reported as a diagnostic where it can be mapped by the
neutral analyzer. It is not the primary cross-paradigm ranking metric.

### Layer 3: Official-QA Selection Control

No method generates new semantic questions. All methods select from the same
official NuScenes-QA pool:

- uniform random selection;
- template-balanced selection;
- neutral footprint-aware selection after official questions are annotated by
  the shared analyzer.

This layer checks whether a coverage-aware selector still helps on a dataset not
generated by ADVTEST.

## Shared Boundary

All methods may share:

- the exact frame list and frame order;
- official NuScenes-QA records associated with those frames;
- raw NuScenes images and metadata;
- the tested VLM and inference configuration;
- the total VLM-call budget;
- the evaluator, answer normalization, logging, and failure deduplication;
- a post-generation neutral footprint analyzer.

Only Layer 1 methods may share the complete programmatically generatable question
space, because Layer 1 explicitly studies selection over a controlled space.

## Forbidden Leakage

External baselines must not read:

- ADVTEST-generated JSONL suites;
- ADVTEST candidate ordering or scores;
- uncovered-gap lists;
- current L0/L1/L2 coverage state;
- ADVTEST `coverage_footprint`, `path_pattern`, `l2_score`, or selection phase;
- another method's generated questions or VLM outputs, except where QAAskeR
  explicitly requires its own initial SUT answer.

The neutral footprint analyzer must derive annotations from the final question,
frame metadata, and scene graph. It must not copy ADVTEST-private annotations.

## Budget Rules

- `generation_budget` is the number of emitted questions. It is the common
  budget for structural coverage and suite-generation comparisons.
- `vlm_call_budget` is the number of tested-model inference calls. It is the
  common budget for cross-paradigm error detection.
- The two budgets must never share a CLI flag, output field, or table column.
- Official seed initialization is charged whenever the method queries the VLM.
- A QATest mutation costs one VLM call.
- A QAAskeR primary question and follow-up cost two VLM calls.
- Offline deterministic generation does not consume VLM-call budget, but its
  wall-clock time is logged separately.
- Layer 1 uses a generated-question budget for coverage curves and additionally
  reports VLM-call-budget results when suites are evaluated.

## Result Tables

- Table A reports L0/L1/L2 coverage and coverage AUC at an equal
  `generation_budget`.
- Table B reports unique failures, calls per unique failure, category diversity,
  and duplicate rate. Every row must have the same actual `vlm_calls`; mixed
  call counts are rejected.
- Table C reports capacity at a requested `vlm_call_budget`. It includes both
  the requested ceiling and actual calls so suite exhaustion remains visible
  instead of being mistaken for equal-budget performance.

## Frame Scheduling

- Every method receives the same deterministic frame order.
- `advtest` may switch early on full coverage or marginal-gain decline because
  adaptive scheduling is part of the method.
- Non-adaptive baselines use only the common per-frame cap, candidate exhaustion,
  and global budget. They may not switch based on observed coverage.
- Sensitivity analysis reports at least two per-frame caps.

## Provenance Contract

Every output question must include:

- `experiment_layer`;
- `experiment_method`;
- `question_source`;
- `source_question_id`;
- `source_sample_token`;
- `generation_adapter`;
- `uses_coverage_feedback`;
- `vlm_call_cost`;
- `global_budget_index`;
- `scene_frame`.

The runner must reject an external-baseline record containing ADVTEST-private
fields before evaluation.

## Initial Implementation Scope

The first implementation increment will:

1. remove QATest and QAAskeR from the structural-coverage runner;
2. add random, template-balanced, object-balanced, L0-greedy, and L1-greedy
   selection policies;
3. prevent non-adaptive methods from using coverage-based frame switches;
4. add provenance fields and leakage validation;
5. add an official NuScenes-QA loader and independent QATest suite builder;
6. run original QAAskeR MR2 Q2S/S2G modules in an isolated persistent process,
   with one primary and one follow-up VLM call per complete pair.
